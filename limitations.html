PlagTrace — Limitations

Compare

This is a screening aid. Only a human reviewer may decide misconduct, after giving the student a chance to respond.

What this tool cannot detect

  • Paraphrase that changes most words: k-gram methods need shared word sequences. Heavy rewording, summarising, and translation fall below the threshold by design.
  • Ideas, structure, or data copied without shared wording; figures, tables, and images.
  • Scanned-image PDFs, encrypted PDFs, and some .docx files with unusual compression.
  • Code that has been restructured (reordered blocks, different algorithm) — token normalisation survives renaming, not redesign.
  • Anything outside the documents you supply: this tool has no web search and no reference database, because it never uploads your text.

Known failure modes

  • False positives from templates, boilerplate, standard phrases, and shared terminology — mitigated, not eliminated, by quote/citation/boilerplate exclusion.
  • False negatives from short documents: with k=5, a document under a few dozen words has too few shingles for a stable score.
  • Scores are not probabilities and not comparable across different settings. Changing k, window, or the minimum threshold changes the result; the report records the settings so a result can be reproduced exactly.
  • There is no AI-text detection in this tool, and none should be inferred from a similarity score.

How to use a result responsibly

Read the highlighted passages. Check whether the match is a quote, a citation, a template, or standard wording. Give the author a chance to respond before any decision. Keep the exported JSON report with its hashes, settings, version, and timestamp as the audit trail.
